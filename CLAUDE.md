## Claude Code specifics

- **Unity MCP** is registered for Claude Code as `unity-mcp` (tools `mcp__unity-mcp__*`; `opencode.json` registers the same relay as `unity` for OpenCode). It only works while the Editor is open. Typical loop after editing scripts: `Unity_GetConsoleLogs` (errors/warnings) → `Unity_RunCommand` for scene/asset work. `RunCommand` scripts can use game types from `Assembly-CSharp` directly (e.g. `Object.FindAnyObjectByType<GameManager>()`, `SerializedObject` to set private `m_` fields).
- **Play-mode checks via MCP:** set `EditorApplication.isPlaying = true` in one `RunCommand`, drive the game in the next (e.g. `PlacementController.DebugSeedCity()`, `GameManager.Clock.DebugAdvanceDays(n)` for instant days, `GameManager.Clock.SetSpeed(...)`, or invoke UI `Button.onClick` directly), then set it back to `false`. `Unity_Camera_Capture` without an id returns the Scene View, not the game camera; to see the game view, render `Camera.main` into a `RenderTexture` and write a PNG to the scratchpad, then read it.
- **Running EditMode tests via MCP:** in a `RunCommand` (not in Play mode, not while compiling), `ScriptableObject.CreateInstance<TestRunnerApi>()`, `RegisterCallbacks` with an `ICallbacks` that appends `RunFinished` counts and failed leaf tests (`!HasChildren && TestStatus == Failed`) to a static `StringBuilder`, then `Execute(new ExecutionSettings(new Filter { testMode = TestMode.EditMode }) { runSynchronously = true })` and `result.Log` the builder — results come back in the same call (add `testNames = new[] { "SimulationTests.Tick_IsDeterministic" }` to the filter for one test). Async runs are unreliable: a pending domain reload drops the callbacks. Batch-mode `Unity.exe -runTests` can't run while the Editor has the project open.
- **Editor closed (or mid-reload), compile check only:** a throwaway SDK-style `.csproj` in the scratchpad (never in the repo, `netstandard2.1`, `EnableDefaultCompileItems=false`) that `<Compile Include>`s `Assets/_Game/Scripts/**` (excluding `**/Editor/**`) and references `C:/Program Files/Unity/Hub/Editor/6000.6.3f1/Editor/Data/Managed/UnityEngine/*.dll`, `Library/ScriptAssemblies/Unity.*.dll` (minus `Unity.AI.*` and `*Editor*`) and `Library/ScriptAssemblies/UnityEngine.UI.dll` catches C# errors. A second project with only `Scripts/Grid/**`, `Scripts/Simulation/**` and `Tests/EditMode/Simulation/**` (+ `Library/PackageCache/com.unity.ext.nunit@*/net472/unity-custom/nunit.framework.dll`) catches asmdef-boundary violations (they must not reference `Assembly-CSharp` types). This does not replace the Test Runner — `ScriptableObject.CreateInstance` and other native calls fail outside Unity.
- **RunCommand quirks:** scripts are wrapped in `Unity.AI.Assistant.Agent.Dynamic.Extension.Editor`, where `Image` resolves to a namespace — alias `using UImage = UnityEngine.UI.Image;`. Nested classes inside `CommandScript` get duplicated by the wrapper (CS1527) — declare helper classes (callbacks, coroutine holders) as top-level `internal` classes. Scripts that call `File.Delete` are rejected ("User interactions are not supported") — delete/restore files from the shell instead. `Unity_GetConsoleLogs` doesn't reliably return plain `Debug.Log` lines; report via `result.Log`, or have coroutines append to a log file in the scratchpad. "Unity not detected" right after editing any script (not just adding one) is the domain reload — wait and retry.
- **Save slot:** `SaveGameController.Save()` / the HUD Save button / F5 write the player's real save at `Application.persistentDataPath/city.json` (`%USERPROFILE%/AppData/LocalLow/DefaultCompany/City Game/city.json`). Copy it to the scratchpad before any test that saves and copy it back afterwards; `SaveGameController.NewCity()` is in-memory only.
- **Balance experiments:** run the pure sim in a `RunCommand` on a `ScriptableObject.CreateInstance<BalanceConfig>()` whose private `m_` fields are overridden through `SerializedObject` — never edit the asset to try values. The seeded-city layout (roads, zones, plant at `(0,9)`, parks at `(5,14)`/`(14,16)`) matches `SimulationTests.RunSeededCity`, so harness numbers translate directly into test assertions.
- **Play mode while the Editor is unfocused:** the player loop stalls (sim won't tick, `ScreenCapture` never writes). Set `Application.runInBackground = true` in a `RunCommand` **after** entering Play mode — set in Edit mode it writes `PlayerSettings.runInBackground` into `ProjectSettings.asset`. To capture Screen Space Overlay UI, temporarily switch the canvas to `ScreenSpaceCamera` with `Camera.main`, render to a `RenderTexture`, then switch it back.
- **Driving real input in Play mode (unfocused Editor):** by default device input doesn't reach game actions (`Pointer` reads (0,0)). In a `RunCommand`: `InputSystem.settings.editorInputBehaviorInPlayMode = AllDeviceInputAlwaysGoesToGameView` and `backgroundBehavior = IgnoreFocus` (no settings asset exists, so this is in-memory only); then `InputSystem.DisableDevice` the real `Mouse.current`/`Keyboard.current` (else the physical mouse overrides) and `AddDevice<Mouse>`/`<Keyboard>` virtual ones. Drive them from a coroutine started on any scene MonoBehaviour (`QueueStateEvent` + `yield return null` ×2 per step; `MouseState.WithButton(MouseButton.Left)` for press/drag; UI buttons via `RectTransformUtility.WorldToScreenPoint(null, …)`, map cells via `Camera.main.WorldToScreenPoint`). Remove the virtual devices and re-enable the real ones in a `finally`. This exercises the EventSystem too (hover, button clicks).
- **Performance checks:** editor frame times mislead (Hierarchy/editor overhead makes GameObject create/destroy look ~5 ms; an unfocused player stalls). Build a development player into the scratchpad via `BuildPipeline.BuildPlayer` (`BuildOptions.Development`, scene `Assets/_Game/Scenes/Main.unity`) and run `CityGame.exe -perfBenchmark -screen-width 1920 -screen-height 1080 -screen-fullscreen 0` — see `PerfBenchmark` in `AGENTS.md`. RunCommand can't use `System.Diagnostics`/`System.Reflection`; time with `Time.realtimeSinceStartupAsDouble`. `result.Log` ignores format specifiers like `{0:F2}` — use interpolated strings.
- **After a player build:** the build (and Play-mode sessions) rewrite `Assets/Settings/*.asset`, `ProjectSettings/*.asset` (shader prefiltering, serialized defaults, Input System `preloadedAssets`) and sometimes `Main.unity` UI layout. These aren't intended changes — `git checkout` them, then reopen the scene with `EditorSceneManager.OpenScene` so the editor doesn't save the stale copy.
- **Scene saves from RunCommand:** saving `Main.unity` serializes layout-driven `RectTransform` values (HUD children) as 0 — Unity's canonical form for driven properties; the committed scene already has it. Save right after `OpenScene` + your edit; don't re-save after the canvas has laid out, or every prefab instance under `UI` gains driven-value overrides. Avoid new cross-prefab references on the HUD instance — put the reference on the new object instead (see `NewCityDialog` → `GameMenu.NewRequested`). Reverting `Main.unity` with git while it's open briefly blocks the MCP bridge; reopen it with `EditorSceneManager.OpenScene`.
- **Shell edits:** in the Bash tool a heredoc whose body contains apostrophes (e.g. C# strings like `"can't"`) can fail to parse even when quoted (`<<'EOF'`). For multi-line patches, write a Python script to the scratchpad with the Write tool and run it.
- **Scene references from RunCommand:** load assets **after** `EditorSceneManager.OpenScene` — `OpenScene(Single)` unloads assets loaded earlier in the same script, and assigning those stale objects serializes `{fileID: 0}`. Check the scene diff after saving.
- **Hand-written assets:** new `.cs` files referenced from a scene or asset need a `.meta` with a GUID before Unity imports them (`fileFormatVersion: 2` + `guid: <32 hex>`); prefer creating assets/scene objects through `RunCommand` when the Editor is open.
