# AGENTS.md

## Project
- Unity **6000.6.3f1**, URP 17.6.0, Linear, PC target, new Input System only (`activeInputHandler: 1`).
- Isometric 2.5D city-builder with an abstract (statistical) simulation. Design, roadmap and the per-system reference: `Docs/GamePlan.md` (§12 roadmap, §13 systems).
- **Roadmap M10–M19** (`Docs/GamePlan.md` §12): the city spans history through 4 ages (Medieval 750, Renaissance 1450, Industrial 1760, Modern 1945) with research, a tech tree and a selectable starting age. M10 (map size, perf, New City), M11 (ages, research, save v2), M12 (local pollution, land value, heritage), M13 (water: wells, towers, pipes, save v3) and M14 (civic services: order, fire, health, education) are **done**; **M15 is next**. Standing rules: see **Roadmap M11–M19** below; where each later milestone plugs in: `Docs/GamePlan.md` §12.
- Game code lives under `Assets/_Game/` (never at `Assets/` root). Default scene: `Assets/_Game/Scenes/Main.unity`.

## Build / run / test
- **No CLI build, lint, or formatter** — the Unity Editor is the build system. Don't invent npm/dotnet build commands.
- Tests run via **Window > General > Test Runner** (`com.unity.test-framework` installed). EditMode unit tests (grid + simulation) live under `Assets/_Game/Tests/EditMode/`. Never `dotnet test`. Without an Editor (cloud sessions), `Tools/sim-harness/run.sh` runs the pure-sim EditMode tests under Mono (a stand-in: a Test Runner pass is still owed; see `unity-test-loop`).
- `Library/`, `Temp/`, `Logs/`, `UserSettings/`, `obj/`, `Build/` are gitignored — never edit or commit.
- `*.csproj` and `City Game.slnx` are generated by Unity — don't hand-edit.

## C# / scripts
- No asmdefs **except** the grid core + simulation core and their tests: runtime code → `Assembly-CSharp`; anything under an `Editor/` folder → `Assembly-CSharp-Editor` (editor-only code must live there or player builds fail). Pure grid logic (`CellUtils`, `GridData`, `ZoneType`, `GridSystem`) lives in `Assets/_Game/Scripts/Grid/CityBuilder.Grid.asmdef`; pure simulation logic (`RoadNetwork` + the M6 sim systems, the M9 power/coverage systems and `BalanceConfig`) lives in `Assets/_Game/Scripts/Simulation/CityBuilder.Simulation.asmdef` (references `CityBuilder.Grid` by `GUID:`). EditMode tests live under `Assets/_Game/Tests/EditMode/` as `CityBuilder.Grid.Tests.asmdef` and `CityBuilder.Simulation.Tests.asmdef` (each references its runtime asmdef by `GUID:`); each test asmdef sits in its own folder (`.../EditMode/` and `.../EditMode/Simulation/`), since Unity allows only one asmdef per folder.
- Input System only — legacy `Input.*` throws at runtime. Game actions: `Assets/_Game/Input/CityBuilder.inputactions` (map `Gameplay`: Pan, Zoom, Pointer, Confirm, Cancel, Rotate, Demolish, RoadTool, PipeTool, SpeedDelta, CycleOverlay, DebugToggle, QuickSave, QuickLoad). `Assets/InputSystem_Actions.inputactions` is the project-wide template — unused by game code. `Pointer` is a **Pass Through** action (M11g): as a Value action it stuck to whichever mouse/pen had the largest position, so a second pointer device (or a virtual one in tests) never moved the map cursor.
- URP: sprites/tilemaps need a URP sprite material (`Universal Render Pipeline/2D/Sprite-Unlit-Default`); built-in `Sprites/Default` renders pink.
- Obsolete APIs: `Object.GetInstanceID()` is a compile **error** (use `GetEntityId()`); `FindFirstObjectByType` is deprecated in Unity 6 — use `FindAnyObjectByType` instead.

## World / scene conventions
- Ground = `Grid` (`Rectangle` layout, `cellSize (1,1,1)`, rotated `-90° X` to lie flat in XZ) + `Ground` Tilemap (square tiles, repainted at runtime to the map size). The `Grid` GameObject sits at `(12,0,12)` and never moves; logical cells `(0..W-1)×(0..H-1)` map to world `[0,W]×[0,H]` (cell center `(x+0.5, 0, z+0.5)`). Tile cell = `(x - 12, 11 - y)` (anchored on the 24×24 ground painted in the scene, `Y↔Z` flip) — `GridSystem.LogicalToTileCell` hides that, so maps of any size grow from the same anchor.
- Main camera is orthographic at 30° elevation / 45° azimuth; square cells read as 2:1 iso diamonds. Buildings stand along world **Y**.
- `Directional Light` is rotated `(50, 240, 0)` so the three visible block faces (top, +X, +Z) get distinct tones on the Simple Lit building materials. Ground/roads/zones are sprite-unlit and ignore it.
- Because the camera is tilted, its XZ position is **not** the point it looks at on the ground — `ApplyBounds` clamps the *ground-look-at* point (ray `transform.forward` → `y=0`), not raw XZ. On start and on `GameEvents.WorldResized` the camera shifts so its ground-look-at point is the map centre (for 24×24 that is the scene position `(36.5, 20, 36.5)`); max zoom = `max(m_MaxZoom, mapSide × m_MaxZoomPerCell)`; the camera also backs off along `-forward` to `max(scene distance 40, 0.75 × mapSide + 10)` (and widens `farClipPlane`) so a big map's near corner isn't clipped.
- Layers: `Ground`=8, `Buildings`=9, `Ghost`=10.
- **Not `IsometricZAsY`** — `Docs/GamePlan.md` §2/§5 is stale on this point.

## Roadmap M11–M19
Each milestone's full plan is its own file, `Docs/milestones/Mxx.md` (M10–M15 exist; M16–M19 are outlines in `Docs/GamePlan.md` §12) — read only the one you need.

**Workflow:** follow the `milestone-workflow` skill — plan in `Docs/milestones/Mxx.md` first, commit each step on its own; a milestone is done when EditMode tests are green, a **UI-only virtual-input play-through** of its loop passes (`virtual-input-playthrough`) and the docs (GamePlan §13 Systems reference + §8/§12 status; this file only if a convention changed) are updated.

**Standing rules (carry these into M12–M19)**
- **Pure sim.** Rules and data live in `CityBuilder.Simulation` (ScriptableObjects referencing buildings by `Id` string; `BuildingDefinition` stays in `Assembly-CSharp`). Runtime code only feeds it (`CityModifiers`, `ServiceSource`) and draws it.
- **The age-less sim is the regression baseline.** `SimulationSystem` built without age/tech databases must keep today's numbers (the legacy seeded-city tests); a new system either stays out of that path or the plan says explicitly which baseline numbers change and why. Industrial start with real content = the accepted M11 baseline (`AgeBalanceTests.IndustrialStart_RealContent_Baseline`).
- **Per-cell state** must survive `GridData.Resize` (reallocate on `OnResized`), and anything tied to growth clears when a cell's level drops to 0 (like built age / historic). Capacity only through `CapacityModel`; growth gates and their explanations through `GrowthSystem` + `GrowthBlocker` (+ `SelectionPanel` text).
- **Saves.** Any new persisted state bumps `SaveData.CurrentVersion` and adds one `SaveMigrations` step with a test (keep `Fixtures/city_v1_24x24.json` migrating); derived state (power, coverage, land value, traffic load…) is recomputed, not saved. Save → load → continue must equal an uninterrupted run, so any randomness needs a seeded RNG whose state is saved.
- **Content** (ages, techs, visual sets) comes from `Tools/gen_age_content.py`; new buildings hang off existing techs via `BuildingDefinition.RequiredTech`. `ContentTests` must stay green (tree valid and reachable).
- **Balance.** Tunables go in `BalanceConfig` (code default = asset value, tagged "(tuned, M1x)"). Re-run `AgeBalanceTests` and extend `EngagedCity`'s player model when a milestone adds something a player must build or manage (e.g. water towers, fire stations) — see `balance-tuning`.
- **Rendering.** Shared materials only (no per-instance materials or `MaterialPropertyBlock`s), pooled objects; re-run `PerfBenchmark` in a player build (`perf-benchmark`) when a milestone adds many renderers or per-frame work.
- **UI patterns.** New events go in `GameEvents` (+ `ResetSubscribers`). Info views: add an `InfoOverlay.View` value + `IsAvailable` rule + a `VIEW` `ToolButton`. Features that need a tech stay hidden until unlocked (the `GameManager.PowerUnlocked` pattern for HUD groups, views and toasts). Panels under the HUD share the `SidePanels` slot.

**Where M13–M19 plug in:** `Docs/GamePlan.md` §12 → *Where M13–M19 plug in (integration notes)*. Decide the details in each milestone's plan.
