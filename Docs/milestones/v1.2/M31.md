# M31 — Release 1.2 (plan, 2026-10-16)

*Live plan: update step notes here as steps are done. Part of the 1.2 roadmap: [`Roadmap.md`](Roadmap.md). Where it
fits: `../../GamePlan.md` §12 (stub + status); systems as built: §13. The release it repeats: `../v1.1/M26.md`.*

## Goal
Ship M27–M30 as Chronopolis **1.2.0** for Windows and the browser, after proving that everything 1.2 added still works
together from the title screen and that performance did not regress.

## Done when
- Version **1.2.0** is the one source (`PlayerSettings.bundleVersion`, `ReleaseBuild.Version`) and shows on the title;
  `Docs/Changelog.md` has the 1.2.0 entry (the five feedback items, in player words), no longer marked draft.
- EditMode green; every committed play-through driver re-run on the final code (one per Play session), plus a new
  `Release12Driver` from the title: straight road drag, demolish drag, research towards an advance with the new cost
  shown, a Low district of each zone (cottages, a market, a farm), save → load.
- `PerfBenchmark` (development player) recorded against M26 / M30.
- Windows release build (`CityBuilder > Build Windows Release`, installer + zip) and `-smokeTest -savesDir <folder>`
  green windowed and full screen; silent install / start / uninstall.
- WebGL build checked in the browser pane against a local server, **including M28's persistence check** (save, refresh,
  closed tab, export / import) and a grown city (the title showcase); Editor switched back to Windows and churn reverted.
- Docs: GamePlan §8 / §12 / §13 status, `AGENTS.md` Project bullet and `CLAUDE.md` header ("M0–M31 are done", 1.2.0).

## Design decisions (defaults the user can change)
| Topic | Default | Why |
|---|---|---|
| Version | **1.2.0** | A feature release on the same save line: no milestone bumped `SaveData.CurrentVersion`, 1.1.0 saves load unchanged. |
| New code | None in the game except the version string; an Editor driver and docs. | A release step must not change behaviour; a found bug is fixed in its own commit first, and the driver that missed it gets a check. |
| Baselines | Unchanged; the benchmark is recorded, not tuned. | M29 / M30 were the last balance changes. |
| Upload to jpm20000.com | **Done by the owner, by hand** (the website is its own repository, not this one): the WebGL `Build/` + `StreamingAssets/` are prepared here, the owner uploads them with a new `BUILD_VERSION` and adds `autoSyncPersistentDataPath: true` to the play page's `config`. The live check (saves from before the upload still listed, a refresh keeps a new save) follows when the owner says it is up. | Publishing to the site is outward-facing and its repository is not in this session. |
| Tag / push | Nothing tagged or pushed unless asked. | Standing instruction. |

## Steps
- **31a — Plan and version.** This file; `ReleaseBuild.Version` and `bundleVersion` 1.2.0; the changelog entry final;
  `Release11Driver`'s version check reads `ReleaseBuild.Version`-independent text (it checks "1.1.0": update it to the
  current version so the old driver still passes).
- **31b — Full regression.** EditMode tests; rerun each committed driver (CameraToolbar, Finish, Controls, Tutorial,
  RepairIcon, RoadLayout, Density, Goods, CustomAssets, Release11, DragTools, LowDensity) on the final code.
- **31c — `Release12Driver`.** One play-through from the title touching each 1.2 feature (above). Reuses the helpers.
- **31d — Performance.** Development player, `-perfBenchmark`, record in the `perf-benchmark` table.
- **31e — Windows release.** `Build Windows Release`, `-smokeTest` at 1280x720 and full screen, silent install / start /
  uninstall, `git status` churn reverted.
- **31f — WebGL.** `WebGLBuild.Build` (twice if the showcase draws no buildings), serve locally, check the title
  showcase, a city, a road drag, and the persistence recipe (F5 → reload → listed; closed tab; export / import); switch
  the Editor back to Windows, EditMode once more; hand the upload to the owner.
- **31g — Close-out.** Status lines (GamePlan, `AGENTS.md`, `CLAUDE.md`), Roadmap, this file, changelog dated.

## Risks
- A player build churns `Assets/Settings` and `ProjectSettings`: commit the version first, build, then `git checkout` the rest.
- The first web build after a Windows session drew no buildings in M28 (shader prefiltering): build twice and look at the showcase.
- The WebGL build leaves the Editor on WebGL; switch back before the Windows release (do the Windows release first).
- Drivers chained in one Play session report false failures: one driver per Play session, frames ticking first.
