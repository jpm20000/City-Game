## Design decisions (defaults the user can change)
| Topic | Default | Why |
|---|---|---|
| Version | **1.2.0** | A feature release on the same save line: no milestone bumped `SaveData.CurrentVersion`, 1.1.0 saves load unchanged. |
| New code | None in the game except the version string; an Editor driver and docs. | A release step must not change behaviour; a found bug is fixed in its own commit first, and the driver that missed it gets a check. |
| Baselines | Unchanged; the benchmark is recorded, not tuned. | M29 / M30 were the last balance changes. |
| Upload to jpm20000.com | **Done by the owner, by hand** (the website is its own repository, not this one): the WebGL `Build/` + `StreamingAssets/` are prepared here, the owner uploads them with a new `BUILD_VERSION` and adds `autoSyncPersistentDataPath: true` to the play page's `config`. The live check (saves from before the upload still listed, a refresh keeps a new save) follows when the owner says it is up. | Publishing to the site is outward-facing and its repository is not in this session. |
| Tag / push | Nothing tagged or pushed unless asked. | Standing instruction. |

## Risks
- A player build churns `Assets/Settings` and `ProjectSettings`: commit the version first, build, then `git checkout` the rest.
- The first web build after a Windows session drew no buildings in M28 (shader prefiltering): build twice and look at the showcase.
- The WebGL build leaves the Editor on WebGL; switch back before the Windows release (do the Windows release first).
- Drivers chained in one Play session report false failures: one driver per Play session, frames ticking first.
