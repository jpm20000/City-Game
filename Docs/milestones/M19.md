# M19 — Release (plan, 2026-10-04)

*Live plan: update step notes here as steps are done. Where it fits: `../GamePlan.md` §12 (stub + status); systems as built: §13.*

**Goal:** City Game becomes something you can hand to someone. It starts on a **main menu** over a living showcase
city instead of dropping straight into an empty Industrial map. Cities are kept as **named saves with thumbnails**,
with quicksave and rotating autosaves. One **Settings** screen holds audio, display, interface (UI scale), gameplay
and **rebindable keys**, and takes over the M18 Sound panel and its `PlayerPrefs`. A new player can choose a
**Medieval tutorial**: a non-blocking objective checklist that walks them from the first dirt road to advancing into
the Renaissance. Last, an Editor menu builds a **Windows release**: a non-development x64 player, a zip and an
installer, checked by a scripted smoke test. The simulation does not change. The save format gains a city name and
the tutorial's progress (v7).

**Done when:**
- Nothing in `CityBuilder.Simulation`'s `Tick` path changes behaviour. All 357+ EditMode tests stay green with
  unchanged numbers (seeded 24² city, `IndustrialStart_RealContent_Baseline` 220 / 0.631, `AgeBalanceTests` off and
  on, budget player).
- **Save v7:** `SaveData.CurrentVersion` 7 with `CityName` and `Tutorial`. One `SaveMigrations` step with a test, and
  `Fixtures/city_v1_24x24.json` still migrates.
- **Saves:** named saves in `<persistentDataPath>/Saves/` (a JSON city, a `.info.json` summary sidecar and a PNG
  thumbnail each), one quicksave per city, three rotating autosaves at the interval from Settings, rename / delete /
  overwrite with confirmation, and a one-time import of the legacy `city.json`. `SaveSlotsTests` covers listing,
  naming, rotation, a missing or corrupt sidecar and the import, all in a temp folder.
- **Front end:** the game boots to a main menu (Continue, New City, Tutorial, Load, Settings, Quit) over the showcase
  city. Esc opens a pause menu (Resume, Save, Save as, Load, Settings, Main menu, Quit) when nothing else wants Esc.
  New / Load / Main menu / Quit and closing the window ask before unsaved progress is lost. `-perfBenchmark`,
  `-smokeTest` and `-skipMenu` bypass the menu.
- **Settings:** one tabbed modal (Audio, Display, Interface, Gameplay, Controls), reachable from both menus and the
  HUD. Everything is stored in `PlayerPrefs` under `CityGame.*`. The M18 keys (`CityGame.Audio.*`,
  `CityGame.Visual.LockDay`) keep their names, so existing settings carry over. UI scale 80–150% works at
  1280×720 through 2560×1440 with no clipped HUD (screenshots).
- **Controls:** every keyboard action except Esc and F1 can be rebound. Overrides persist
  (`SaveBindingOverridesAsJson`), conflicts swap with a notice, and there is a reset per row and for all.
- **Tutorial:** a Medieval tutorial city (Tutorial on the main menu, or a New City option) shows 12 objectives in
  order, highlights the button each one needs, explains a blocked growth step with the existing `GrowthBlocker`
  text, survives save / load, and can be skipped. A harness test proves a scripted player finishes it on the shipped
  content in ≤ 120 game days.
- **Release:** *CityBuilder → Build Windows Release* produces `Build/Release/CityGame_<version>/`,
  `CityGame_<version>_win64.zip` and, with Inno Setup installed, `CityGame_<version>_setup.exe`. The release player
  passes `-smokeTest` (new city, 60 days, save, load, equal, exit 0) with no errors in `Player.log`. It also starts
  and is playable at 1280×720 windowed and at the desktop resolution full screen. Version, icon and window settings
  are set. `PerfBenchmark` (development player) stays within the M18 budget.
- A **UI-only virtual-input play-through** from the main menu passes (tutorial start, objectives ticking, pause menu,
  Save as with a thumbnail, Load, Settings changes taking effect, a key rebind used in play, back to the main menu).
- **Owed to a human** (recorded, not blocking): a playtest of the installed release, and the M18 audio listen.

## Design decisions (defaults — change any before the step that uses them)

| Topic | Decision |
|---|---|
| Tutorial style | **Asked 2026-10-04: objective checklist.** Non-blocking: a card at the side lists the current objective (title, one or two sentences, progress like "4 / 6 homes"), with the finished ones ticked above it. A pulsing outline highlights the toolbar / HUD button the objective needs. The game keeps running and every tool stays usable. Skip ends the tutorial (with a confirmation). |
| Saves | **Asked 2026-10-04: named saves + autosave.** No limit on named saves. One quicksave per city (`<city>_quick`), overwritten by F5. Three autosaves (`autosave_1..3`, the oldest is overwritten) every N game months: Off / 1 / 3 / 6, default 3. F9 loads the newest save of the current city, or the newest save overall when the city has none. |
| Main menu backdrop | **Asked 2026-10-04: showcase city.** A bundled save (`Assets/StreamingAssets/showcase.json`, made by an `[Explicit]` harness generator from `EngagedCity`, so the pieces are the real content) is loaded behind the menu. It runs at 1× with disasters off, so day/night, vehicles and ambience run. The camera drifts slowly along a loop, and input to the map is off. Nothing about it is ever saved. Continue / New / Load replace it. |
| Release scope | **Asked 2026-10-04: zip + installer.** Non-development Windows x64 player, a zip and an Inno Setup installer (Start menu shortcut, optional desktop shortcut, uninstaller that **keeps** saves and settings). No store SDK. **Inno Setup is not installed on this machine.** The build menu writes the `.iss`, runs `ISCC.exe` when it finds it, and otherwise produces the zip and logs that the installer is owed. Installing Inno Setup 6 (free) is the user's step. |
| One scene | The menus are overlays in `Main.unity`, built at runtime like `BudgetPanel` / `SoundPanel` (M15 lesson: no prefab or scene diff, and the play-through drives them by name). A separate menu scene would mean re-wiring every scene reference and a second load path for nothing. |
| Menu mode | `GameFlow` (new, runtime) owns the state: `MainMenu` / `Playing` / `Paused`. In `MainMenu`, the HUD canvas group is hidden and non-interactive, `PlacementController` and the camera input are off, and the clock runs at 1× on the showcase. `Paused` keeps the HUD visible but blocks it, and the clock is paused (the previous speed is restored on Resume, like `EventPopup`). `GameEvents.FlowChanged(GameFlowState)` is new. |
| Esc routing | `EscapeRouter` (new, runtime): handlers register with a priority, and one Esc press goes to the highest one that accepts it. The order is confirm dialog > settings / save browser > New City dialog > event popup (refuses: it needs a choice) > active placement tool (cancel, today's behaviour) > open side panel (close) > pause menu (open / close). `PlacementController` and `NewCityDialog` move their `CancelPressed` checks into handlers, so one key press never does two things. |
| Unsaved changes | `SaveGameController.Dirty`: set by any `OnCellChanged`, placement, research / budget change, or game day ticked since the last save or load. A New City or a load counts as clean. Quitting through `Application.wantsToQuit` (the window's X too) asks Save / Don't save / Cancel when dirty. The showcase is never dirty. |
| City name | New City gets a name field (default: a generated name from per-age word lists, e.g. "Ashford", "Kingsbridge"). It is stored in `SaveData.CityName` (v7), shown in the HUD date line, and is the default save name. Migrated saves get `""`, shown as "Unnamed city". |
| Save files | `Saves/<name>.json` (the city, unchanged format), `<name>.info.json` (`SaveSummary`: city name, age index and name, population, money, date, map size, real time saved (UTC ticks), save version, game version, kind Manual / Quick / Auto, tutorial yes / no) and `<name>.png` (320×180 thumbnail). The browser lists summaries only, so it never parses a 96² city. A missing or unreadable sidecar is rebuilt from the save on first listing, and a save that fails to read is listed as damaged (delete only). File names come from `SaveSlots.SanitizeName` (strips invalid characters, reserved Windows names and trailing dots, max 48, unique by suffix). Writes go to `.tmp` and are then replaced, so a crash mid-save keeps the old file. |
| Legacy save | On first start, if `<persistentDataPath>/city.json` exists and `Saves/` has no `Imported city`, it is **copied** (never moved) to `Saves/Imported city.json` with a sidecar and no thumbnail (placeholder). |
| Thumbnails | Rendered from the main camera into a 640×360 `RenderTexture` through URP's `RenderPipeline.SubmitRenderRequest` (`UniversalRenderPipeline.SingleCameraRequest`), downsampled to 320×180 and written with `EncodeToPNG`. The overlay UI is not in camera renders, so there is no HUD in the shot. The fallback is `ScreenCapture.CaptureScreenshotAsTexture` at end of frame with the HUD canvas hidden for that frame. Info views are forced off for the shot (day/night stays as it is: a night thumbnail is fine). |
| Save path protection | `SaveSlots.Root` can be overridden (`-savesDir <path>` on the command line, or a static set by Editor scripts). The play-through, Play-mode checks and the smoke test point it at the scratchpad or a temp folder, so they never touch the player's saves. This replaces the "back up city.json" ritual in `CLAUDE.md`. |
| Settings storage | `GameSettings` (static, `PlayerPrefs`, `CityGame.*`, lazy reads, a `Changed` event per section) absorbs `SoundSettings` and `DayNightCycle.LockToDay` (same keys). Display settings use Unity's own `Screen` state, plus `CityGame.Display.*` for VSync / frame cap. `Apply` runs once at boot from `GameFlow`. A Reset button per tab. |
| Settings content | **Audio:** master, music, ambience, effects, mute. **Display:** window mode (Full screen / Borderless / Windowed), resolution (from `Screen.resolutions`, deduplicated by size, highest refresh rate), VSync, frame cap (30 / 60 / 120 / unlimited when VSync is off). **Interface:** UI scale 80–150% in steps of 10, Lock to day, camera pan speed, edge-scroll on / off (the code exists, it is off today), tooltips delay. **Gameplay:** autosave interval, default Disasters & events switch for New City, pause on event popup (today: always), confirm demolish of placed buildings. **Controls:** the rebind list. |
| UI scale | Every `CanvasScaler` (`ScaleWithScreenSize`, 1920×1080, match 0.5) gets `referenceResolution = 1920×1080 / scale`. Runtime-built panels sit under the HUD canvas, so they follow. `ToolbarController`'s overflow fit keeps working (it measures the canvas). The minimum supported window is 1280×720. At 1280×720 the default scale is effectively 0.67 of 1080p, so text legibility at small windows is a 19d check, and the reason the 80% floor exists. |
| HUD buttons | Save / Load / New / Sound become **Save** (save to the current city's last save, or Save as when it has none) · **Menu** (pause menu) · **Settings** (opens at its last tab). The F5 / F9 keys stay. `GameMenu` keeps its name (the play-through and the scene reference it). |
| Rebinding | Keyboard bindings only: Pan up / down / left / right (primary + secondary, i.e. WASD and arrows), Rotate, Demolish (Delete + Backspace), Road tool, Pipe tool, Speed pause / 1× / 2× / 4×, Cycle view, Quicksave, Quickload. Esc (Cancel), F1 (debug) and the mouse are fixed. `InputReader` keeps the cloned asset, exposes it, and loads `CityGame.Input.Bindings` before `Enable`. A rebind uses `PerformInteractiveRebinding` with Esc cancelling, excluding the mouse and fixed keys. A key already bound to another listed binding **swaps** the two, with a toast. Tooltips and the tutorial text show the current key (`InputReader.KeyLabel(action)`). |
| Tutorial setup | Medieval, 48², disasters **off**, normal starting money, city name "Tutorial town" (editable). `SaveData.Tutorial` = the index of the current objective (−1 = no tutorial, 12 = finished). The card can be minimised. Finishing shows a short "what next" message (fire, plague, research ahead) and offers to turn disasters on. |
| Tutorial objectives | See *Content*. Each objective is a pure condition over the city (in `Simulation/Tutorial/`, read-only, so it is testable and never touches `Tick`) or a UI flag the runtime sets (panel opened, view used). Objectives are sequential. Conditions are checked once per game day and on `CellChanged` / `TechCompleted` (cheap counts), and one already met when it becomes current completes at once. |
| Tutorial help | When the current objective waits on growth, the card shows the top `GrowthBlocker` across the city's zoned cells with the `SelectionPanel` wording ("No water — dig a well within 3 cells"). It reuses the explanation text, so it is not a second copy of the rules. |
| Version | `PlayerSettings.bundleVersion` is the one source (today 0.1.0). The release step sets **1.0.0** (or the user's pick). It is shown on the main menu and in each save summary. |
| Product identity | Today `companyName` is `DefaultCompany` and `productName` is `City Game`. **Changing either moves `persistentDataPath`** (and with it saves and settings). Decision needed before 19g, see *Open questions*. Until then the plan assumes they stay, and the legacy import also checks the old folder if they change. |
| Debug in release | `DebugPanel` and `PerfBenchmark` are already development-only (`Debug.isDebugBuild`). The release step adds a check that no `DEBUG`-labelled UI is reachable in a non-development player (the smoke test logs the DebugPanel's state). `-smokeTest` works in release players on purpose: it is how the release is verified. |

## Content

**Tutorial objectives (Medieval; tunable text in `TutorialContent`):**

| # | Objective | Done when | Highlights |
|---|---|---|---|
| 1 | Lay a road | ≥ 8 road cells connected to the map edge | Road tool |
| 2 | Zone homes | ≥ 6 residential cells beside a road | Residential zone |
| 3 | Dig a well | a Well is placed | Well |
| 4 | First villagers | population ≥ 10 | — (blocker help) |
| 5 | Shops and crafts | ≥ 4 commercial and ≥ 4 crafts (industrial) cells zoned | Commercial, Crafts zones |
| 6 | Check the books | the Budget panel opened (UI flag) | Budget button |
| 7 | Start research | any research active | Research button |
| 8 | A village green | Commons researched and a Park placed | Research, Park |
| 9 | Read the land | any info view opened (UI flag), e.g. Water or Happiness | View buttons |
| 10 | A growing village | population ≥ 60 | — (blocker help) |
| 11 | Seat of learning | a Monastery placed (needs Masonry → Monasticism) | Research, Monastery |
| 12 | A new age | the Renaissance reached (RP, techs and 120 people; the Research panel's checklist) | Research / Advance |

**Generated city names:** per-age lists of prefixes and suffixes (e.g. Ash / Kings / Mill / Stone + ford / bridge /
ton / bury) in `CityNames` (runtime). Seeded from the clock, never from `SimRandom`.

256 / 128 / 64 / 48 / 32 / 16 px into `Art/Icon/`. It is set as the default icon in `PlayerSettings`. Replaceable by hand.

## Architecture

**Pure (Simulation asmdef; read-only towards the sim):**

| New / changed | Notes |
|---|---|
| `Save/SaveData` | v7: `CityName` (string), `Tutorial` (int, −1). `CurrentVersion` 7. |
| `Save/SaveMigrations` | v6 → v7: `CityName = ""`, `Tutorial = -1`. Test `Migrate_V6_To_V7` + the v1 fixture chain. |
| `Save/SaveSlots` (new) | `Root` (overridable), `List()` → `SaveSummary[]` newest first, `SanitizeName`, `UniqueName`, `PathsFor(name)`, `Write(name, data, summary, png)` (tmp + replace), `Delete`, `Rename`, `NextAutosave()` (rotation by oldest), `QuickName(city)`, `ImportLegacy(oldPath)`. `System.IO` only, no `UnityEngine` (the PNG is bytes passed in). |
| `Save/SaveSummary` (new) | The sidecar, plus `From(SaveData, kind, savedUtc, gameVersion, ageName)`. |
| `Tutorial/TutorialObjective`, `TutorialContent`, `TutorialProgress` (new) | Objective = id, condition kind + numbers, UI flag, highlight target name (string). `TutorialProgress.Evaluate(SimulationSystem, GridData, flags)` advances the index. No state of its own beyond the index (saved in `SaveData`). |
| `SimulationSystem` | No change. If a query is missing (e.g. "road cells connected to the edge" for objective 1), it is added as a read-only helper with a test. |

**Runtime (`Assembly-CSharp`):**

| New / changed | Notes |
|---|---|
| `Scripts/Core/GameFlow.cs` | State machine (MainMenu / Playing / Paused), boot (settings apply, legacy import, showcase load, command-line bypasses), quit hook, autosave timer (on `GameEvents` month change). |
| `Scripts/UI/EscapeRouter.cs` | See Esc routing. |
| `Scripts/UI/MainMenu.cs`, `PauseMenu.cs`, `SaveBrowser.cs`, `ConfirmDialog.cs`, `SettingsPanel.cs`, `KeybindList.cs`, `TutorialCard.cs`, `UiHighlight.cs` | Runtime-built (the `SoundPanel` pattern). Shared helpers for panels, buttons, sliders, tabs and toggles go into a `UiKit` static, factored out of `BudgetPanel` / `SoundPanel` (they already build the same controls). `SoundPanel` is folded into `SettingsPanel`'s Audio tab and removed. |
| `Scripts/Save/SaveGameController.cs` | Multi-slot: `Save(name, kind)`, `SaveAs`, `QuickSave`, `Autosave`, `Load(name)`, `LoadData(SaveData, readOnly)` (the showcase), `Dirty`, `CurrentSaveName`, thumbnails (`ThumbnailCapture`). `Apply` stays the one rebuild path. |
| `Scripts/Core/GameSettings.cs` (replaces `Audio/SoundSettings.cs`) | Sections and `Changed` events. `AudioController`, `DayNightCycle`, `IsoCameraController`, `ToolbarController` / `CanvasScaler` and `EventPopup` read it. |
| `Scripts/Input/InputReader.cs` | Exposes the actions, loads / saves overrides, `KeyLabel`, `SetGameplayEnabled(bool)` for menu mode. |
| `Scripts/UI/NewCityDialog.cs` | Name field + Tutorial toggle, built at runtime under the existing panel (the M17 Disasters toggle pattern). |
| `Scripts/Editor/ReleaseBuild.cs` | Menu *CityBuilder → Build Windows Release*: checks for a clean `git status` (warns), sets nothing in `ProjectSettings` that is not already committed, builds `StandaloneWindows64` without `Development`, zips (`ZipFile.CreateFromDirectory`), writes `Build/Release/CityGame.iss` from `Tools/installer/CityGame.iss.template` with the version, and runs `ISCC.exe` from the standard install paths if present. Prints a summary (sizes, paths, what was skipped). |
| `Scripts/Core/SmokeTest.cs` | `-smokeTest [-savesDir <tmp>]`: skip menu → New City Medieval 32² → roads, zones and a well through the controllers' public API → 60 days at 4× → save → load → compare population, money and date → write `smoke_test.txt` → `Application.Quit(0 / 1)`. Works in release and development players. |
| `Tools/showcase` (`[Explicit]` test `ShowcaseGenerator`) | Runs `EngagedCity` from Medieval on 48² until the Industrial age (so the built ages mix), records placed buildings as `BuildingRecord`s (the harness gains a placed-building list), and writes `Assets/StreamingAssets/showcase.json` with disasters off. Re-run only when content changes. |
| `PerfBenchmark` | Skips the menu (it already builds its own city). |
| Play-through driver | Starts from the main menu, uses `-savesDir`-style override (`SaveSlots.Root`) to the scratchpad. |

## Standing rules check

- **Pure sim / age-less baseline:** no `Tick` change. New Simulation code is either save plumbing (`SaveSlots`,
  `SaveSummary`, migration) or a read-only evaluator (tutorial). Every recorded number stays.
- **Saves:** v7 adds persisted state (`CityName`, `Tutorial`), so there is one migration step with a test, and the v1
  fixture keeps migrating. The save → load → continue equality is unaffected (no new randomness in the sim; city
  names use their own RNG).
- **Per-cell state:** none new. Thumbnails, menus and the tutorial hold no per-cell arrays.
- **Content generator:** no age / tech changes. Tutorial text, city names and the showcase are separate content with
  their own generator (`ShowcaseGenerator`) or tables.
- **Balance:** the tutorial's harness test is the balance check for the tutorial path. `AgeBalanceTests` unchanged.
- **Rendering:** menus are UI only. The showcase city is smaller than the benchmark city. The thumbnail render is
  one extra camera render on save, not per frame.
- **Presentation reads the sim:** the menus and the tutorial read state and call the same controller methods the
  HUD calls. The showcase run is a normal sim run that is thrown away.
- **UI patterns:** new events (`FlowChanged`, `TutorialAdvanced`, `SettingsChanged` if not local) in `GameEvents`
  + `ResetSubscribers`. Panels built at runtime. The settings panel is a modal, not a `SidePanels` member, because it
  is reachable from the main menu where the HUD is hidden.

## Risks / open questions

- **Open — game title and company (needed before 19g).** `productName` "City Game" and `companyName`
  "DefaultCompany" are placeholders that end up in the window title, the installer, the Start menu and the save
  folder (`LocalLow/<company>/<product>`). Changing them moves saves and settings. The legacy import handles the
  move, and `PlayerPrefs` (registry, also keyed by company / product) would reset unless copied. 19g copies the
  `CityGame.*` keys over once. Also open: the release version (default 1.0.0).
- **Inno Setup not installed.** The installer step degrades to "zip only, installer owed" until the user installs
  Inno Setup 6. Code-signing is out of scope, so SmartScreen will warn on the unsigned installer and exe (record
  this in the release notes).
- **URP camera render requests** for thumbnails are new to this project. If `SubmitRenderRequest` misbehaves with the
  2D tilemaps or the day/night tint, the end-of-frame screen capture with the HUD hidden is the fallback (one frame
  without the HUD, which could flicker; acceptable on an explicit save, and autosaves capture smaller).
- **Esc routing touches input handling everywhere.** Moving `CancelPressed` checks into one router can break the
  "cancel the tool" muscle memory. The play-through checks every layer, and the router logs which handler took
  the press in development builds.
- **Menu mode vs the sim:** the showcase runs real ticks behind the menu, so a long stay on the menu grows that city
  (harmless, never saved). Events and disasters are off for it. A load from the menu must fully replace it,
  including `SimRandom` and the budget, which `Apply` already does.
- **Showcase generator coupling:** `EngagedCity` places sim-only sources today. It needs a building list it can
  write as `BuildingRecord`s that `PlacementController.RestoreBuilding` accepts (ids, origins, rotations,
  footprints). A mismatch shows as skipped buildings when the showcase loads, which 19c checks for at 0.
- **Rebinding and the Pass Through pointer:** only keyboard bindings are touched, and `Pointer` stays as M11g left
  it. Composite (WASD) parts are rebound per part, and the arrow keys are a second composite.
- **UI scale × toolbar overflow:** the toolbar's own fit and a larger scale compound. If 150% at 1280×720 can't fit,
  the setting's maximum is limited by the window size (the slider shows what applies).
- **Tutorial pace:** at the shipped balance, Medieval → Renaissance takes ~84 engaged days; a new player is slower.
  If `TutorialPlaythroughTests` shows objective 12 is far from the rest, end the tutorial at objective 11 and show
  the advance as a closing tip instead. The decision is recorded in the 19f note.
- **The release player differs from the Editor:** stripping, missing shaders (URP variants stripped from a
  non-development build) and `StreamingAssets` paths. The smoke test and a look at a screenshot of each age in the
  release build catch these, and `ContentTests` cannot.
