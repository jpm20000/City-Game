# M20 — Camera & toolbar (plan, 2026-10-05)

*Live plan: update step notes here as steps are done. Part of the 1.1 roadmap: [`Roadmap.md`](Roadmap.md). Where it fits:
`../../GamePlan.md` §12 (stub + status); systems as built: §13 (Camera, Input, UI).*

**Goal:** the three IMPORTANT items from the 1.0 feedback. The player can **rotate the camera** to see the city from
all four sides. The **Buildings** section of the toolbar stops growing with every unlock: buildings sit in a few
**group buttons** that open a flyout (Services › Watch House, Constabulary, …). The New City dialog's **Disasters &
events** and **Guided tutorial** switches show whether they are on. The **View** section folds the same way. Nothing
in the simulation, the save format or the balance changes.

**Done when:**
- Q / E (rebindable, listed in Settings › Controls) rotate the view by 90° with a short animation; the toolbar has
  rotate buttons too. In all four views: clicking, dragging roads / zones, placement ghosts, the selection outline,
  info views, floating text, fire, vehicles and the day/night lights work; WASD pans relative to the screen; the
  camera bounds and zoom-to-cursor hold; buildings show three distinctly lit faces (screenshots of the same corner of
  a grown 48² city from all four views). The rotation is kept per session (not saved in the city); New City / Load
  reset it to the default view. The showcase drift behind the main menu still works.
- The Buildings section shows at most **five group buttons** (Utilities, Services, Health, Education, Parks — see
  *Content*), each hidden until one of its buildings is unlocked. Clicking a group opens a flyout above it with that
  group's unlocked buildings (icon, name, cost, tooltip as today); picking one starts placement and closes the
  flyout; Esc / right-click / clicking elsewhere closes it (`EscapeRouter`). A group's button shows the last building
  picked from it, so repeated placement is one click. Unlocking a building flags its group (dot) until opened.
  New buildings file themselves into a group from their data, with no toolbar edit.
- The View section is one **Views** button (plus the existing V cycle key): its flyout lists the available views
  (Power, Water, Parks, Pollution, Value, Traffic, Ages, Crime, Fire, Health, Schools) and Off; the button shows the
  active view's name. V still cycles.
- The New City dialog's two switches show a clear checked / unchecked box and an "On" / "Off" state; while Guided
  tutorial is on, Disasters & events shows Off and is greyed (the tutorial forces it off, which today is invisible).
- At 1280×720 and UI scale 80–150% the toolbar fits without the overflow scale-down kicking in for a fully unlocked
  Modern city (screenshots).
- All EditMode tests green with **unchanged numbers**. The committed play-through drivers (`FinishDriver`,
  `ControlsDriver`, `TutorialDriver`) are updated for the flyouts and pass; the tutorial's button highlights point at
  the group button, then the item inside the open flyout. A new UI-only virtual-input play-through of the M20 loop
  passes (rotate four times and place / zone in each view, build from two groups, switch views via the flyout,
  New City with both switches toggled).
- Docs: §13 Camera / Input / UI, §12 stub, this file.

## Design decisions (defaults — change any before the step that uses them)

| Topic | Decision |
|---|---|
| Rotation steps | **Asked 2026-10-05: 90° snaps**, four views (azimuth 45°, 135°, 225°, 315°), elevation unchanged at 30°. Animated with a smooth step over 0.25 s (unscaled time, so it works paused). Input during the animation queues one further step. Free rotation is out: the 2:1 diamond look, the tile art and the lighting were made for the diagonal views. |
| Rotation pivot | The ground-look-at point (ray `forward` → `y = 0`), so the city turns around the screen centre. Distance and zoom are kept. |
| Keys | New `Gameplay` actions **RotateCameraLeft = Q**, **RotateCameraRight = E** (the building **Rotate** stays on R). Both added to the rebind list (`SettingsPanel` Controls tab) and to `InputReader`. Middle-mouse drag rotation: not in M20 (it would need free rotation). |
| Toolbar buttons | Two small ⟲ / ⟳ buttons at the right end of the Tools section, tooltips with the current key (`InputReader.KeyLabel`). |
| Lighting | The `Directional Light` yaw turns with the camera (240° + the view's offset), so the top / left / right faces keep the same tones in every view. It is presentation only (no sim effect); `DayNightCycle` drives intensity and colour as today and must read the yaw it is given, not overwrite it. |
| Sorting | `CameraSortAxis` recomputes `transparencySortAxis` from the camera's forward on every rotation (it is set once in `Awake` today). |
| Pan | Pan input is mapped through the camera's yaw (screen up = away from the camera on the ground), so W always moves "up the screen". `ApplyBounds` already clamps the ground-look-at point, which doesn't depend on yaw. |
| Facing | Building prefabs already face their street (`CellUtils.FacingRoad`). The back and street-side faces become visible from some views; the kit has full meshes, so no art change is planned. If a kit piece has missing faces it is fixed in `BuildingKitGenerator` in 20d. |
| Persisted view | Kept for the session in `IsoCameraController` (not in the save, not in `PlayerPrefs`): New City and Load return to the default view (azimuth 45°, so 1.0 screenshots and thumbnails match). |
| Groups | Derived from data: `Category == Utility` → **Utilities**; `CivicKind` Order / Fire → **Services** (the feedback's "Services"); `CivicKind` Health → **Health**; `CivicKind` Education or `ResearchPerDay > 0` → **Education**; a `Service` with `HappinessEffect > 0` and no civic kind (Park, Fountain) → **Parks**. An optional `BuildingDefinition.ToolbarGroup` override (enum, default Auto) lets a later building or a custom asset (M25) choose. The rule lives in one static `ToolbarGroups.For(def)` with an EditMode test over the shipped database (every placeable has a group, no group empty in every age). |
| Flyout | Built at runtime under the toolbar canvas (M15 lesson: no prefab diff), one per group, re-using the existing building `ToolButton` instances (moved, not duplicated, so the placement wiring, cost colouring and tutorial highlight keep working). Opens above its group button, one row, scrolls sideways past 8 items. Only one flyout open at a time. |
| Group button | Shows the group's icon and name; once a building has been picked from the group, the label reads "Services ▸ Police Station" in small type and **clicking the main area re-picks it**, the ▴ part opens the flyout. Keyboard: none in M20 (number-key groups are a candidate for M25). |
| New dot | A small dot on a group button when a building in it was unlocked since the group was last opened (tracked in memory, reset per session — not saved). |
| Views flyout | Same flyout component as the groups. The M14 Services view cycle button and the M16 Traffic copy are folded into it; `InfoOverlay.IsAvailable` decides which entries show. The V key keeps cycling through available views. |
| Toggle fix | `NewCityDialog.BuildToggle` uses `DefaultControls.CreateToggle` with empty `Resources`, so the box and checkmark are untextured white Images on a white panel: the state can't be seen. Replace with a `UiKit.Toggle` (dark box with an outline, an accent-coloured checkmark, and the label suffixed "— On" / "— Off"), and reuse it in `SettingsPanel` wherever toggles exist so every switch in the game looks the same. Disabled state = 50% alpha + not interactable. |
| Tutorial ↔ disasters | Turning Guided tutorial on sets Disasters & events off and disables it (label "Off in the tutorial"); turning the tutorial off restores the previous disasters choice. Same behaviour today, now visible. |

## Architecture

- **Runtime only.** `IsoCameraController` (rotation state, animation, yaw-relative pan), `CameraSortAxis`
  (public `Apply()`), a small `LightYaw` hook for the directional light, `InputReader` (two actions), the
  `.inputactions` asset (two actions + bindings), `ToolbarController` (groups + views), a new `ToolbarFlyout`
  (`Scripts/UI/`), `ToolbarGroups` (static rule; `Assembly-CSharp`, since `BuildingDefinition` lives there),
  `UiKit.Toggle`, `NewCityDialog`, `SettingsPanel` (rebind rows), `TutorialCard` / `UiHighlight` (highlight path
  through a group).
- **Events:** `GameEvents.CameraRotated(int view)` (+ `ResetSubscribers`) for anything that caches screen-space
  directions (vehicle / floating-text billboards if any, `CursorHint`).
- **No change** to `CityBuilder.Simulation`, `CityBuilder.Grid`, `SaveData` or content.

## Risks / open questions

- **Picking after rotation.** `PlacementController` uses a ground raycast, so it should be correct in any view; any
  code that converts screen deltas to cells by a fixed 45° (drag direction for roads, the R building rotation, the
  `CursorHint` offset) has to read the camera's yaw. Search for `45` / `0.7071` before 20d.
- **Building rotation key R** means "rotate the ghost" during placement; with the camera rotatable, a ghost's
  "facing" should stay relative to the world, not the screen. Check in 20d.
- **Back faces of the kit.** Never seen in 1.0; a piece with missing faces or odd windows needs a generator fix (20d).
- **Tutorial text** names buttons ("click Well in the toolbar"); with groups it should say "Utilities › Well". The
  objective text lives in `TutorialContent`; update it in 20b.
- **Browser keys:** Q / E are safe in WebGL; nothing to guard. Ctrl+W style shortcuts are not used.
