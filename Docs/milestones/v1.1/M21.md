# M21 — Progression & feedback (plan, 2026-10-05)

*Part of the 1.1 roadmap: [`Roadmap.md`](Roadmap.md) (order and shared decisions). Where it fits:
`../../GamePlan.md` §12; systems as built: §13.*

## Goal
Three small fixes from the feedback list: research should not run away from the player ("research scales too
quick"), the Avenue must not be available before the Paved Road, and a broken-down building should show a repair
icon in the world instead of waiting to be clicked.

## Done when
- Each age takes noticeably longer than in 1.0 with the engaged player (probe numbers below), the Medieval age and the
  guided tutorial are unchanged, `AgeBalanceTests` are green with their new ranges.
- On any path into the Industrial age Macadam (Paved Road) is researched before Electric Trams (Avenue); `ContentTests` green.
- Every broken-down plant / pump shows a repair icon over it; the icon goes when it is repaired or demolished;
  the same presenter can show more statuses later without a new system.
- UI-only play-through of the loop passes; docs updated.

## Design decisions (defaults the user can change)
| Topic | Default | Why / alternative |
|---|---|---|
| What "slower" means | Tech costs ×1.0 / ×1.5 / ×2.0 / ×2.0 by the tech's age; the cost to advance into the Industrial age ×2, into Modern ×2.5; Medieval and the advance into the Renaissance unchanged | Costs are content (`Tools/gen_age_content.py` scales), so no new code path and no save change. The Medieval age and the tutorial stay as they are (the tutorial's ≤ 120-day bound). Alternative: diminishing RP per job as population grows (code in `SimulationSystem`, changes more tests). |
| Avenue prerequisite | Electric Trams requires Macadam (as well as Electricity) | A city that advances (not starts) into the Industrial age has no Macadam; a city that starts there has it as a starting tech, so nothing changes for that path. |
| Repair icon | A world-space billboard sprite over each broken source, on the shared UI sprite material, pooled; `StatusIcons` reads the sim | Presentation reads the sim, never writes it; statuses are a small enum so fire / no power / no water / no road can be added later. |

## Measured before changing anything (probe `ResearchProbe`, engaged player, Medieval start, 64×64)
| | Medieval | Renaissance | Industrial | Modern reached |
|---|---|---|---|---|
| 1.0 | 84 d | 61 d | 57 d | day 202 |
| RP/day at the end of the age | 12 | 52 | 90 | |

RP/day grows about as fast as the costs do, so each age got *shorter* (the advance cost 250 / 1,200 / 3,000 is most of
the time); raising only tech costs gave 84 / 70 / 69 (day 223), so the advance costs are the main lever.

## Steps
- **21a. Research costs** — `TECH_COST_SCALE` / `ADVANCE_COST_SCALE` in the generator, probe, `AgeBalanceTests` ranges (later ages 60–120 d), notes.
- **21b. Paved before avenues** — Macadam as a prerequisite of Electric Trams; `ContentTests`.
- **21c. Repair icon** — `StatusIcons` presenter (pooled billboards), a small sprite generated in code, hooked to `DisasterSystem.Broken` through `GameManager`.
- **21d. Play-through and docs** — driver check that a breakdown shows the icon and Repair clears it; GamePlan §12 / §13, `AGENTS.md`, `CLAUDE.md`, roadmap.

## Risks
- Slower research moves the Modern-start and disaster balance a little (seed 3 with the budget player dips to 0.528
  happiness; Modern start grows ×1.97 not ×2 between day 60 and 120): recorded in the tests, not tuned away.
- The icon must not break draw-call counts: one shared material, pooled, no per-instance materials.
