# M26 — Release 1.1 (done 2026-10-06)

*Live plan: update step notes here as steps are done. Part of the 1.1 roadmap: [`Roadmap.md`](Roadmap.md). Where it
fits: `../../GamePlan.md` §12 (stub + status); systems as built: §13. The 1.0 release it repeats: `../v1.0/M19.md` (19g).*

## Goal
Ship **Chronopolis 1.1.0**: the same Windows installer and zip as 1.0.0, the WebGL build, and a changelog, after proving
that everything M20–M25 added still works together from the title screen and that performance did not regress.

## Done when
- Version **1.1.0** is the one source (`PlayerSettings.bundleVersion`, `ReleaseBuild.Version`) and shows on the title.
- EditMode tests green; every committed play-through driver passes against the final code.
- A new `Release11Driver` play-through, UI-only from the title screen, touches each 1.1 feature in one session.
- `PerfBenchmark` (development player) is within the M18 / M19 / M23 / M24 numbers.
- Windows release builds; `-smokeTest` passes (windowed and full screen); the installer installs, starts and uninstalls.
- WebGL builds; the build runs in a browser (title, New City, camera rotation, a toolbar flyout, the Build menu search box).
- `Docs/Changelog.md` lists 1.1.0; GamePlan §12 / §13, `AGENTS.md`, `CLAUDE.md` status lines say 1.1 is released.

## Design decisions (defaults the user can change)
| Topic | Default | Why |
|---|---|---|
| Version | **1.1.0** (outline) | A feature release on the 1.0 save line; saves are v10 and old saves migrate. |
| Changelog | One file, `Docs/Changelog.md`, player-facing wording, newest first, 1.0.0 as a short entry. | There was none; the installer and web host take the text from it. |
| New code | None in the game except the version string. Only an Editor driver and docs. | A release step must not change behaviour; a found bug is fixed in its own commit first. |
| Baselines | Unchanged; the benchmark is recorded, not tuned. | M24 was the last baseline change. |

## Steps
- **26a — Plan and version.** This file, `ReleaseBuild.Version` and `ProjectSettings` to 1.1.0 (Apply Release Settings), `Docs/Changelog.md`.
- **26b — Full regression.** EditMode tests; rerun each committed driver (Finish, Controls, Tutorial, CameraToolbar, RepairIcon, RoadLayout, Density, Goods, CustomAssets) on the final code.
- **26c — `Release11Driver`.** One play-through from the title: New City, camera turn, toolbar flyouts, Build menu search, avenue pair and one-way highway, density, Industrial age with goods, a custom building, save / load. Reuses the driver helpers.
- **26d — Performance.** Development player, `-perfBenchmark`, record in the `perf-benchmark` table.
- **26e — Windows release.** `Build Windows Release`, `-smokeTest` at 1280x720 and full screen, silent install / start / uninstall, `git status` churn reverted.
- **26f — WebGL.** `Build WebGL`, serve `Build/WebGL` locally, check it in the browser pane, switch the Editor back to Windows.
- **26g — Close-out.** Docs status lines, roadmap table, tag nothing unless asked.

## Risks
- A player build churns `Assets/Settings` and `ProjectSettings`: commit the version first, build, then `git checkout` the rest.
- The WebGL build leaves the Editor on the Web profile; switch back before any further desktop work.
- A bug found late (for example in a view the drivers never open) is fixed on its own commit, and the driver that missed it gets a check.
