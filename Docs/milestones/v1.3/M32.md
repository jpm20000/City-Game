# M32 — UI art (plan, 2026-10-16)

*Where it fits: `../../GamePlan.md` §12 (stub); systems as built: §13 *UI (M7)*; art sizes and the ChatGPT prompt
blocks: [`../../UiArtSizing.md`](../../UiArtSizing.md).*

## Goal
The UI gets real artwork (icons, framed panels, buttons, meters) generated by the owner with ChatGPT, without
changing what any panel does. Today every panel, button and meter is a flat-coloured `Image` (the palette lives in
`UiKit`) and the only UI sprite is the main-menu logo.

## Done when
- Every toolbar tool, group, view and service / utility building button shows an icon; the HUD readouts have icons.
- Panels, dialogs, tooltips, toasts, buttons and meters use framed (9-sliced) art where the owner supplied it, and the
  old flat look wherever a sprite is missing.
- EditMode green; a UI-only virtual-input play-through passes (every earlier driver still finds its buttons by name);
  `perf-benchmark` and the WebGL build size re-checked; GamePlan §12 / §13 updated.

## Design decisions (defaults; the owner can change any of them)
| Topic | Default | Why / alternative |
|---|---|---|
| Art source | The owner generates PNGs by hand in ChatGPT with the blocks in `Docs/UiArtSizing.md` and drops them in the untracked `Data/ui_raw/<kind>/` | Scripted OpenAI API calls (repeatable, but costs per run and needs a key); not wanted (asked 2026-10-16) |
| Art scale | Shipped at **3x design size**, imported at **300 pixels per unit** so a 9-slice border draws at its design size on the 100 PPU canvas | 4K (x2) at the top UI scale 150% is x3; 2x would blur there |
| Where the theme lives | One `UiTheme` ScriptableObject at `Resources/UiTheme.asset`, read through `UiTheme.Current` | `UiKit` is static and builds most panels in code, so it can't take a serialized reference; a `GameManager` field was the alternative |
| Missing asset / sprite | The code defaults are today's colours and no sprites: a missing theme or slot is the old look, never an error | Standing rule for presentation |
| Colour with a sprite | The slot's colour still tints the sprite (`Image.color`); neutral (light grey) art is tinted, full-colour art sets that slot's colour to white | Lets one grey button serve every state and the zone colours |
| Prefab UI (HUD, toolbar, tool buttons, side panels) | A small `UiThemed` component (slot name) paints its `Image` from the theme on `Awake` (32d) | Editing each prefab's sprites by hand; the component keeps the theme in one asset |
| Per-age skins | Optional step 32e, decided after the first art is in | One skin for all ages |
| Sim / saves / baselines | None: presentation only, no `SaveData` change, every baseline unchanged | — |

## Architecture
- **`Scripts/UI/UiTheme.cs`** (Assembly-CSharp, presentation): colours (the `UiKit` palette plus the few fixed widget
  colours UiKit carries), sprite slots (panel, window, tooltip, toast, button, field, meter track / fill, toggle box /
  tick, slider handle; icons later), font (none = TMP default). `UiTheme.Current` loads `Resources/UiTheme`, else a
  code-default instance. `Paint(Image, Sprite, Color)` sets the colour and, when the sprite is set, the sprite with
  `Sliced` (it has a border) or `Simple`.
- **`UiKit`** reads every colour and widget sprite from `UiTheme.Current`; its colour names stay (`UiKit.PanelColor`
  ...) so the 15 callers don't change.
- **Art pipeline (32b):** `Tools/gen_ui_art.py` slices / keys / trims / resizes `Data/ui_raw` into
  `Assets/_Game/Art/UI/<kind>/`; an editor `AssetPostprocessor` for that folder sets Sprite, 300 PPU, the 9-slice border
  from the script's table, mipmaps on for icons only; one UI sprite atlas.

## Steps
- **32a. Theme plumbing (no visual change).** `UiTheme` + `Resources/UiTheme.asset` with today's colours and no
  sprites; `UiKit` colours and widgets (window, button, input field, slider, toggle) go through it. Tests: the asset
  equals the code defaults; `Paint` leaves an `Image` as before with no sprite and slices a bordered one. Check: the
  menus, Settings, Budget and a dialog look the same in Play mode. — done (2026-10-16): `Scripts/UI/UiTheme.cs` +
  `Resources/UiTheme.asset` (hand-written YAML, empty sprite slots); `UiKit`'s colour names became properties reading
  the theme, so no caller changed; `UiTheme.Paint` / `ApplyFont` in every `UiKit` widget. `CityBuilder.Art.Tests` now
  references `UnityEngine.UI` (for `Image` in `UiThemeTests`). EditMode 511 passed (508 + 3). Play mode: the theme
  loads from the asset, of 277 UI images only the logo has a sprite, the window panel is (0.10, 0.12, 0.16, 0.97)
  and the buttons (0.24, 0.27, 0.33) / accent (0.30, 0.55, 0.92) as before; the main menu with Settings open looks
  unchanged. No virtual-input driver: nothing a player clicks changed.
- **32b. Art pipeline.** `Tools/gen_ui_art.py` (grid sheets + a names file per sheet, green key, trim, resize to the
  `UiArtSizing.md` ship sizes), the import postprocessor and the atlas; a test that every sprite under `Art/UI` is
  imported as specified. Needs the first sheets from the owner.
- **32c. Icons.** `ToolButton` gets an icon above its label (label and cost kept; the button names unchanged);
  `BuildingDefinition.Icon` (null = text only, as today) and the toolbar's tool / group / view icons from the theme;
  HUD readout icons. Toolbar width re-checked at 1920 (it scales itself down when full).
- **32d. Frames and buttons.** `UiThemed` on the prefab images (HUD bar, toolbar, tool buttons, selection / tax / tech
  panels, toasts, tooltips); `UiKit` windows, buttons, fields, sliders, toggles and meters take the theme sprites.
- **32e. Font and per-age skins (optional).** A TMP font asset in the theme; a skin per age if the owner wants one.
- **32f. Checks + docs.** UI-only play-through (all drivers), `perf-benchmark` (UI draw calls), WebGL build size,
  screenshots at 100% and 150% UI scale, GamePlan §12 / §13, changelog.

## Risks / open questions
- ChatGPT sheets drift in style between generations; regenerate rather than hand-fix (tips in `UiArtSizing.md`).
- Icons may push the toolbar past 1920; it already scales itself down, but labels might need to shrink.
- `ToolButton` colours mean state (active / affordable); a tinted sprite must keep that readable.
